# Changelog

이 플러그인의 모든 주요 변경사항을 기록합니다.
형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를 따르며,
[Semantic Versioning](https://semver.org/lang/ko/)을 준수합니다.

## [0.4.0] - 2026-10-20

### Added
- 업체·기간·상품 조건의 전체 합계와 20개 옵션 단위 화면 페이지네이션, 불변 운영 보고서 저장·목록·재조회 및 100행 단위 전체 상세 분할 인쇄.
- 보고서별 업체명·시간대·기간·집계 기준 버전·생성 시각·생성자·현재 분석·집계 결과와 당시 상세 보존. 재생성은 별도 UUID 버전이며 재출력은 원본 주문/상품을 다시 읽지 않는다.
- `live_reports`, `live_report_rows` 및 기간/원장 조회 복합 인덱스 추가 migration. 기존 업무 행·QR·원장 변경 없음.

### Changed
- 기간 발생 주문액·누적 입금 확인액 차이·취소·반품·환불 기록과 현재 미입금/현재 주문 상태/현재 잔여 상품금액을 구분. 기간 순매출 및 회계상 매출 인식은 제공하지 않음.
- 누적 수량 상한 대신 DB 조건 조회·집계와 전체 전이 검증을 사용. 보고서 조회/생성은 REPEATABLE READ의 비잠금 일관 읽기이며 업체 쓰기 잠금을 획득하지 않는다.
- 상품 조건의 주문액/차감/재고는 해당 상품, 입금·환불·현재 미입금은 해당 상품 포함 주문 전체 기준으로 명시.
- 공개 서비스/라우트 확장을 검토하고 번들 manifest 소비자를 전수 스캔: 의존 확장 없음. 코어 공개 API 및 g7_version 변경 없음.

### Fixed
- DB 집계로 전환하면서도 상태·위치·최초 입고의 엄격한 비교가 collation의 대소문자 무시 규칙으로 완화되지 않도록 바이트 단위 비교 및 회귀 검증 적용.

## [0.3.0] - 2026-10-20

### Added
- 신규·복사 상품과 다중 옵션 입고를 한 트랜잭션으로 확정하는 업체별 입고 배치, 입고 내역 필터와 배치 QR 재출력.
- 발생일별 주문·입금 차액·취소·반품·환불 및 이동 원장 기반 기초/기말 재고를 구분하는 매출정산 운영 장부와 전체 행 인쇄.
- 계정 정보를 유지하는 본사 비밀번호 재설정, 업체 선택 자동 로드와 저장 상태/오류 안내.

### Fixed
- 공식 신규 설치 시 초기 시드 migration 전에 런타임 오토로드를 등록.
- 옵션 중복 생성 방지, 라벨의 200개 초과 조용한 잘림 방지와 배치 외 QR 혼입 차단.

### Changed
- 상품관리에서 등록·입고·입고 내역·QR 출력을 연결하며 독립 QR 사이드 메뉴 제거. 기존 주소와 권한 보존.
- 소급 입고와 확정 배치 일괄 취소는 미지원. 원장 삭제 없이 기존 물품별 재고 조정/정정 절차 사용.
- 코어 공개 API 변경 없음. 번들 manifest의 의존 관계 전수 확인 결과 이 플러그인에 의존하는 확장이 없어 다른 확장의 최소 버전 상향 대상 없음.

## [0.2.0] - 2026-10-12

### Added
- 업체별 승인 도메인, 고객·직원 인증 범위 및 세션 버전 무효화, 본사 계정 발급·임시 비밀번호·권한 관리.
- 독립 라이브 상품·방송·판매 링크·장바구니 라인 UUID·무통장 주문 및 입금 검토·재고 예약·QR 입출고 원장.
- 주문 원본 스냅샷 보존, 귀속 정정·계좌 변경 안내, 취소·반품·환불 및 인센티브 누적 대사·지급·회수 기록.
- 판매자 업무 화면, 고객 계정·배송지·통관부호·비밀번호 재설정, QR 라벨 선택·입고 묶음 출력 및 요청 이력.
- 매분 예약 만료·인센티브 대사 명령과 격리 회귀 테스트. 실제 송금·유료 API 호출은 제공하지 않습니다.

### Changed
- 루트 웹 라우트가 승인 도메인 라우트를 명시적으로 소유해 라우트 캐시 재생성 후에도 유지합니다. 기존 guard·내부 식별자·골프 배경은 유지합니다.
- 기존 미귀속 계정은 삭제하지 않고 본사 확인 후 명시적으로 전환합니다.
- 공개 API 소비 번들 확장을 전수 검색했으며 의존 확장이 없어 다른 확장의 최소 버전 제약 변경은 없습니다. 루트 라우트 연결은 기존 코어 API 시그니처를 변경하지 않습니다.

## [0.1.4] - 2026-10-12

### Changed
- 고객 화면의 브랜드를 공개 판매자 `live_tenants.name`으로 통일하고 포털 판매자 컨텍스트를 서버 설정으로 분리합니다.
- 소유 판매자의 계정 화면에 브랜드 이름 검증·저장을 연결합니다. 내부 식별자, 회원 및 도메인 검증은 유지합니다.
- 의존 확장을 스캔했으며 이 플러그인의 공개 API를 소비하는 번들 확장은 없어 다른 확장 버전 제약 변경은 없습니다.

## [0.1.3] - 2026-10-12

## [0.1.0] - 2026-09-10

Phase 0 기술 스파이크. 라이브커머스 기능은 없습니다.

### Added

- `Route::domain()` 기반 TeeWide 도메인 라우트 (`teewide.portal`, `teewide.live.tenant`).
  코어 `PluginRouteServiceProvider` 가 프리픽스를 강제하므로 프로바이더 `boot()` 에서
  직접 등록합니다.
- `TeeWideHostGate` — TeeWide 호스트에서 기존 쇼핑몰 SPA·검색·이커머스 API 가 노출되지
  않도록 차단합니다. 코어 확장 미들웨어 자가 게이트(`everything`/`before_core`)로 붙습니다.
- `ConfigureTeeWideSession` — TeeWide 요청의 세션 쿠키를 `teewide_session` /
  `.teewide.com` 으로 바꿉니다. **StartSession 보다 먼저** 실행되도록 라우트 자체 스택의
  첫 자리에 둡니다.
- `TeeWideHost` — 포트·대문자·후행 점·공백·IPv6 를 정규화하고, 정확히 일치할 때만
  TeeWide 로 판정합니다.
- Phase 0 진단 라우트(JSON). `TEEWIDE_DIAGNOSTICS=false` 면 등록되지 않습니다.
- PHPUnit 4개 스위트와 vendor 불필요 하네스 `tests/TeeWide/yutiv-live-commerce-check.php`.

### Notes

- **기본 비활성.** `TEEWIDE_ENABLED` 기본값이 false 라, 플러그인을 번들 상태로 두거나
  설치·활성화만 해도 기존 yutiv.com 은 아무 영향을 받지 않습니다.
- 코어 파일(`app/`, `routes/`, `config/`, `bootstrap/`)과 루트 `composer.json` 은
  **한 줄도 수정하지 않았습니다.**
- `Route::domain()` 은 route:cache 시 호스트를 박습니다. 호스트 변경 후 재캐시가 필요합니다.
- 차단은 404 이며 리다이렉트하지 않습니다.
