## 작업 기준과 구조

시작 기준: main / `88ca7956eb5bdb676f581270626e02003247ae0a`, Git 작업 트리 깨끗함.
운영 서버 HEAD와 동일하다고 가정하지 않습니다. 기존 Golfif 이미지와 메인 스타일을 보존합니다.

기존 `live_tenants`와 `teewide_users`를 보존하고 라이브 전용 업무를 같은 플러그인에 추가합니다.
기존 공개 판매자·인증·세션·브랜드 계약을 재사용할 수 있으므로 독립 모듈을 중복 설치하지 않습니다.

업체별 도메인은 등록·활성 매핑만 신뢰합니다. 고객과 직원 계정은 업체에 귀속합니다.
기존 계정은 tenant_id가 NULL인 확인 대기 상태로 보존하며, 운영자 확인 없이 일괄 귀속하지 않습니다.
기존 소유자 관계도 자동으로 여러 업체의 권한으로 복제하지 않습니다.

판매자: **승인된 업체 호스트**의 `/seller/login`, `/seller/dashboard`.
고객: 같은 업체 호스트의 `/`, `/shop`, `/cart`, `/my`, `/orders/{uuid}`.

   상태, 예약 분, 반품 일수를 저장합니다. 폼의 새 업체는 API 경로 tenant=0을 사용합니다.

   이 저장은 DNS/TLS를 설정하지 않습니다. 미등록 호스트·다른 업체 도메인·코어 호스트는 허용하지 않습니다.

4. 재발급은 같은 직원 선택 후 수행합니다. 기존 비밀번호·세션은 즉시 무효가 됩니다.
   권한 회수·잠금도 session_version을 증가시킵니다. 영업 직원이 owner를 발급할 수 없습니다.
5. 기존 tenant_id=NULL 계정은 자동 귀속하지 않습니다. 본사에서 신원·소속을 확인한 뒤
   기존 계정 전환 폼에 대상 계정과 사유를 기록합니다. 이전 소유자 FK만으로 직원 권한을 부여하지 않습니다.

`owner`: 모든 업체 업무. `sales`: 상품·방송·주문 조회·통계.
`warehouse`: 입출고·재고·라벨·주문. `finance`: 계좌·입금·환불 기록·정산·통계·주문.
`customs`: 통관 조회·배송·주문. 메뉴 숨김 외에도 모든 POST에서 서버 권한을 검사합니다.
통관번호는 암호화 저장하고 고객에게 마스킹합니다. 업무 조회는 감사 기록을 남깁니다.
발급 비밀번호, 재설정 토큰, 통관번호 원문은 일반 감사 JSON에 기록하지 않습니다.

## 실제 운영 순서

1. **입금계좌**: 은행·예금주·계좌를 등록하고 기본 계좌를 선택합니다.
2. **유튜브 채널 / 쇼호스트**: 실제 채널 및 진행자만 등록합니다. YouTube·카카오·텔레그램 URL은 HTTPS 허용 호스트로 제한합니다.
3. **상품 / 상품 옵션**: 상품코드·공개/판매 상태, 옵션·가격·할인을 저장합니다. 로고·상품 사진은 업로드하며 원격 URL을 서버에서 가져오지 않습니다.
4. **입고**: 옵션·수량·위치를 선택하면 개별 UUID가 생성됩니다. 위치 이동·A/S·불량·망실·폐기는 원장에 추가 기록합니다.
5. **방송**: 방송 시간과 별도 판매 가능 시간, 채널, 진행자 지분, 채널/진행자 비율을 입력합니다. 비율은 UI의 %를 서버 경계에서 10000 단위로 변환합니다.
6. **방송 판매 상품**: 방송과 옵션을 연결합니다. 동일 옵션 재고는 방송 간 공유합니다. 종료된 방송을 임의 재개하지 않습니다.
7. **판매 링크**: 방송·채널·진행자·옵션·상담 수단을 선택합니다. 서버가 생성한 불투명 코드만 유입 귀속의 근거로 사용합니다.
   판매 링크 QR, 상품/옵션 QR(`P:`), 개별 물품 QR(`U:`)은 목적이 다릅니다. 출고는 `U:`만 허용합니다.
8. 고객은 링크 또는 상품 화면에서 장바구니에 담고 로그인·배송지를 선택하여 주문합니다.
   로그인 병합은 UUID와 최초 귀속을 유지합니다. 동일 옵션도 귀속이 다른 줄은 합치지 않습니다.
9. 담당자가 **실제 입금액**을 기록합니다. 불일치·만료 후 입금은 검토 상태이며 자동 출고되지 않습니다.
   재고 재예약과 금액 대사를 마친 뒤 입금 검토를 완료합니다. 전량 취소 건은 환불 검토 대상으로 남습니다.
10. 출고 주문 선택 → QR 스캔/붙여넣기 → 읽기 전용 미리보기 → 수량 확인 → 출고 확정.
    일부 물품만 출고하면 부분 출고입니다. 카메라가 지원되지 않아도 USB 스캐너·수동 입력을 사용할 수 있습니다.
11. 실제 배송 확인 후 배송 완료 기록 → 고객 구매확정 또는 반품기간 경과 → 확정 인센티브.
    반품 요청은 검토 보류를 걸고 물품 QR로 실물을 확인합니다. 분쟁 검토 완료는 별도 버튼입니다.
12. 정산은 **승인·지급 사실 기록**입니다. 실제 송금·환불 API는 없습니다. 동일 요청 키 재전송은 같은 결과를 반환합니다.

주문 스냅샷은 원본 가격·할인·계좌·귀속·비율·반품기간을 보존합니다.
계좌 변경 안내 및 귀속 정정은 별도 before/after 이벤트입니다. 고객 계좌 변경 안내는 주문 화면에 게시되며 외부 메시지 발송이 아닙니다.
지급 후 귀속 정정·취소·반품으로 생긴 부족액은 회수 기록을 마치기 전 새 지급을 막습니다.
취소와 환불 기록이 연이어 들어와도 순매출과 인센티브를 두 번 차감하지 않습니다.
판매 후 A/S는 반품·취소와 다른 입출고입니다. 반품·A/S 화면의 전용 폼으로 물품을 맡고 수리 완료 출고를 기록합니다. 판매 수량·인센티브는 유지하며 입고 전 상태로 돌아갑니다.
최신 위치·재고 조정은 물품 이력 화면에서 사유를 적고 정정할 수 있습니다. 과거 원장을 수정하지 않으며 후속 작업이 있으면 거절합니다.

### 계산 예

할인 후 상품 합계 100,001원, 채널 3%, 진행자 그룹 5%이면 채널 3,000원,
진행자 그룹 5,000원입니다. 공동 진행 60%/40%는 3,000원/2,000원입니다.
배송비는 기준에서 제외합니다. 현재 초기 주문 배송비는 0원이며 별도 배송 요금 정책은 추가하지 않았습니다.
3개 상품의 채널 금액 9,000원을 지급한 뒤 1개 반품이면 누적 회수 부족액 3,000원입니다.
같은 반품의 환불을 기록해도 다시 3,000원을 회수하지 않습니다.
통계의 채널·쇼호스트별 수치는 같은 매출의 분석 축이므로 서로 합산하지 않습니다.
기간 매출은 업체 시간대 기준이며 재고·원장 요약은 현재 전체 상태입니다.

## 설정·배포·복구 절차 (이 작업에서 서버 실행하지 않음)

배포 담당자가 먼저 DB, 업로드 저장소, APP_KEY·환경 설정, 설치 확장과 이전 코드 전체를 안전하게 백업합니다.
암호화된 주소·계좌·통관번호를 복원하려면 **원래 APP_KEY도 반드시 보존**해야 합니다.
업무 쓰기를 중지하고 검증된 릴리스와 루트 라우트 브리지를 반영한 다음 공식 업데이트를 실행합니다.

```sh
php artisan plugin:update yutiv-live_commerce --source=bundled --force
php artisan plugin:vendor-verify yutiv-live_commerce
php artisan route:cache
```

새 설치는 `php artisan plugin:install yutiv-live_commerce`, `php artisan plugin:activate yutiv-live_commerce` 순서입니다.
코어 설치·admin 역할·관리자 템플릿이 준비된 정상 G7 인스턴스에서 실행합니다. 운영 전체 재시딩·migrate:fresh를 실행하지 않습니다.
`TEEWIDE_ENABLED=true`, 기존 root/live host 및 `TEEWIDE_BRAND_TENANT`를 확인합니다.
업체별 신규 호스트는 본사 도메인 등록을 사용합니다. 공유 부모 도메인 세션으로 새 업체를 묶지 않습니다.
`TEEWIDE_DIAGNOSTICS=false`를 권장합니다. 계정 메일은 `LIVE_ACCOUNT_MAIL_ENABLED=true`와
기존 승인된 메일 설정을 준비한 경우에만 켭니다. 발신 주소·인증 도메인을 임의 변경하지 않습니다.
로컬 검증은 Mail::fake 또는 발송 비활성 상태만 사용합니다.

배포 후 각 승인 호스트의 로그인 전/후, 임시 비밀번호 강제 변경, 판매자 역할, 고객 소유 주문,
업체 간 접근 차단, 정적 자산, 예약 만료를 합성 데이터로 확인합니다. 실제 고객 주문을 테스트하지 않습니다.
문제 발생 시 신규 업무 쓰기를 중지하고 로그·원장을 보존합니다. 데이터 생성 뒤에는 down()이나 이전 코드만 덮어쓰지 않습니다.
호환되는 전진 수정이 우선이며, 복원이 필요하면 백업 시점 이후 쓰기 손실을 검토한 뒤 코드·DB·저장소·키를 일치시켜 복원합니다.
이벤트 및 원본 스냅샷을 보존한 채 `live:maintain`을 재실행해 원장을 대사합니다. DB 잔액·스냅샷 직접 수정은 하지 않습니다.

## 스케줄러

`Plugin::getSchedules()`가 `live:maintain --batch=100 --seconds=45`를 매분 등록합니다.
전용 워커나 외부 큐는 필요하지 않습니다. **Laravel scheduler 하나를 권장**하며 서버에 기존 설정이 있다고 가정하지 않습니다.
배포 담당자가 서비스 계정으로 다음 cron 한 줄을 확인·등록합니다(경로/PHP 바이너리는 실제 환경 확인).

```cron
* * * * * cd /var/www/yutiv-g7 && /usr/bin/php artisan schedule:run >> storage/logs/scheduler.log 2>&1
```

직접 명령과 scheduler를 중복 등록하지 않습니다. DB+prefix별 MySQL GET_LOCK을 쓰기 연결에서 획득하므로 겹친 실행은 즉시 종료합니다.
배치 기본100/최대200, 루프 처리 예산 최대45초입니다. 이는 개별 SQL 실행까지 강제 중단하는 하드 제한은 아닙니다.
업체 행 잠금 동안 DB 쓰기만 하고 외부 통신은 하지 않습니다. 실패한 건 이후 캐시 커서를 전진시키지 않으며 다음 실행에 재개합니다.
커서가 끝나면 0으로 돌아와 늦게 변경된 주문도 다시 대사합니다. 캐시 소실은 재대사만 유발하며 중복 지급을 만들지 않습니다.
예약 만료는 주문별 멱등 키, 인센티브는 원본/정정 스냅샷과 현재 누적 상태를 기준으로 부족한 원장 delta만 추가합니다.

## 프린터

구매·연결 기준: XP-365B, USB, Windows 지원 드라이버, 감열 라벨 50×30mm, 203dpi.
공식 제조사/공급업체 드라이버를 사용하고 Windows 용지 크기를 50×30mm로 설정합니다.
판매자 QR 라벨에서 입고 배치/단일 물품을 선택 → 선택 라벨 인쇄/PDF → 배율100%, 여백0,
머리말·꼬리말 끄기 → 드라이버 용지 크기 확인 → 합성 1장으로 위치·농도·QR을 확인합니다.
인쇄 요청 감사 기록은 실제 출력 완료 증명이 아닙니다. 장치·브라우저 오차를 실제 시험 라벨로 보정하세요.
카메라는 HTTPS와 사용자의 권한이 필요합니다. 미지원·거부·오프라인 시 자동 재고 변경은 없습니다.

## 로컬 검증과 재현

검증 환경은 Windows의 별도 체크아웃, PHP **8.4.26**, MySQL **8.4.11**, 테이블 prefix `it_`입니다.
대상 PHP **8.3.6 / MySQL 8.0.46** 실행 환경은 사용 가능하지 않아 해당 버전 실행 검증은 미완료입니다.
운영 파일·DB·회원 데이터·메일 발송·외부 API를 사용하지 않았습니다.
PHPUnit은 테스트 전용 .env.testing과 별도 DB가 필수이며 migrate:fresh가 실행됩니다.
브라우저 공식 설치본과 PHPUnit의 BootTime 테스트 프로바이더를 한 로딩 경로에서 중복 등록하지 마세요.
공식 설치/활성화 브라우저 검증과 bundled 전용 PHPUnit 검증을 별도 단계로 운영합니다.
동시성 테스트는 `LIVE_TEST_ALLOW_COMMIT=1` 및 이름에 `isolated`가 포함된 폐기 가능한 DB에서만 실행합니다.
자식 PHP에는 같은 연결·키를 환경으로 전달하며 read/write PDO의 DB를 검증합니다. 자식은 migration을 실행하지 않습니다.

```sh
# 반드시 폐기 가능한 격리 checkout 안에서, 브라우저 서버 종료 후 순차 실행
LIVE_TEST_ALLOW_COMMIT=1 php vendor/bin/phpunit plugins/_bundled/yutiv-live_commerce/tests/Feature
php artisan plugin:build yutiv-live_commerce --production
php artisan plugin:vendor-verify yutiv-live_commerce
```

실제 장비 프린터·스마트폰 카메라·SMTP·DNS/TLS·은행 송금은 미검증입니다.
합성 데이터와 로컬 브라우저 통과를 운영 배포/외부 연동 성공으로 해석하지 마세요.
