# 0.6.0 상품 재고 통합·업무용 회계관리

## 메뉴와 입력 흐름

상품 목록 → 옵션·입고 배치·QR 출력 이력·실사/조정. 독립 재고 주 메뉴는 제거했다. 기존 입고·옵션·상품/물품 UUID와 QR 출력 구조를 재사용한다. 실사 초안은 시스템 수량과 재고 revision을 보존하고, 확인한 실제 QR만 조정한다. 입출고·예약 변경 후에는 기준 갱신이 필요하다. 예약 물품 부족 처리, 미식별 초과 물품 자동 생성은 허용하지 않는다. 초과 미등록 물품은 정상 입고 후 재확인한다.

회계관리 → 현황 / 매출·입금·미수 / 매입·지출 / 계좌·자금 이동 / 재고 자산·체류 / 보고서·관리 마감. 과거 통계·운영 장부·입금계좌 URL과 저장 운영 보고서는 유지한다. 인센티브는 기존 자격 판정·확정·지급/회수 원장을 재사용한다.

상품의 물품 링크에서 기존 원장 이력·상태/위치 변경·마지막 조정 정정도 사용한다. 원장은 20건씩 조회하며 기존 전이·사유·예약 보호를 그대로 거친다. CNY 물품은 원통화 단가·고정 환율과 해당 QR에 실제 배분된 KRW 원가를 구분해 표시한다.

지출 창 → 원통화·금액·고정 환율·출처·발생일·분류 입력 → 지급 여부 선택 → 지출 전표 → 분할 지급/회수 → 자금 거래 → 보고서. 같은 입고 배치는 하나의 매입 전표만 연결한다. 기존 수기 재고 매입 전표와 입고를 연결할 때 통화·금액 대사가 맞아야 한다. 입고 지급은 매입 채무 결제이며 즉시 운영비가 아니다. 증빙은 StorageInterface에 암호화하여 보관하고 권한 있는 다운로드만 제공한다.

## 확정한 집계 기준

사용자 결정: **출고 시 관리매출·대응 FIFO 원가 인식**, **초과 입금은 고객 예수금**, **실제 보유 물품으로 기초층 확정 후 후속 거래부터 FIFO**.

| 자료 | 기준과 처리 |
|---|---|
| 주문 발생액 | 주문 생성일, 주문 당시 상품가격. 미출고 취소는 출고 관리매출을 만들지 않는다. |
| 관리매출/원가 | 출고 movement 시 주문 행 가격과 옵션별 FIFO 배분을 기록. 배송 완료/구매확정은 기존 인센티브 자격 기준을 유지. |
| 반품/손실 복원 | 발생 movement 시 해당 실제 물품의 원래 미복원 배분을 역으로 복원. 새 임의 단가로 계산하지 않는다. |
| 취소·반품 내역 | 해당 업무 발생일에 별도 표시. 관리매출에 반영된 반품을 입금·환불과 다시 합쳐 차감하지 않는다. |
| 수동 입금/환불 | 실제 확인 기록일의 이번 금액. 누적액은 서버에서 합산한다. 입금은 회계상 매출의 근거가 아니다. 은행 연동/송금 없음. |
| 예수금/미수 | 현재 잔여 상품대금·배송비와 누적 입금·실제 환불의 차이. 과입금은 출고 기준 매출을 늘리지 않는다. |
| 운영 지출 | 발생일의 확정 전표, 고정/변동과 inventory/operating/fee/asset 처리 구분. 재고 매입·자산 취득을 운영비에 넣지 않는다. |
| 인센티브 | 기존 원장의 confirmed 증감이 관리 비용, payment/recovery는 실제 자금 흐름. 일반 지출을 자동으로 중복 생성하지 않는다. |
| 환전·이체 | 요청은 잔액 무변동. 출금 확인 후 출금 자금만 차감, 수령 확인 후 수령 자금 증가. 원금은 비용 제외, 별도 수수료만 비용. 반환 대기는 원금이 복구된 것이 아니다. |
| 잠정 관리손익 소계 | 출고 관리매출 − 대응 FIFO 원가 − 손실/복원 − 발생 운영비/비용형 수수료 − 이체 수수료 − 확정 인센티브 증감. |
| 현재 상태 분석 | 조회 기간 생성 주문의 현재 paid·누적 취소/반품 잔여 상품금액. 출고 기준 기간 관리매출과 분리. |

원통화는 2자리, 환율은 6자리, KRW는 거래별 half-up 정수. 금액 곱셈은 십진 문자열/정수 연산을 사용한다. 부분 지급/회수와 물품별 원가 배분은 누적 비례 반올림 차이로 마지막 합계를 원금에 맞춘다. 원통화 0과 미등록/null을 구분한다. 실제 확인일은 미래 입력을 막으며, 소급 유출은 기록일과 이후 자금 잔액이 음수가 되는지 확인한다.

집계 기준 버전은 `management-shipment-fifo-opening-2`. 누락·미확정 항목이 있으면 관리손익 소계는 null/‘미확정’이며, 등록 금액만의 참고 산식 소계를 별도로 보존한다. 원가 합계는 등록된 원가의 합이며 미등록 원가를 0원으로 확정하지 않는다. 적용 시작 전 출고가 포함된 기간도 불완전 기간으로 표시한다. 자금 흐름은 거래 원장에 기록된 금액이며 기존 계정 미연결 확인 기록은 별도 대사 대상이다.

이체의 예상/실제 수령액은 **순수령액**이다. 수수료 지급 자금이 수령 자금이면 수령 때 총수령과 차감 수수료를 한 트랜잭션으로 분리해 최종 잔액은 순수령액만 늘린다. 이 수수료는 실제 수령 환율로 확정한다. 다른 자금에서 내는 수수료는 출금 확인 때 별도 지급한다. 수령 전 예상 잔액으로 수수료를 지급하지 않는다. 환전 취소는 원금 전액 실제 반환 확인을 지원하며 부분 반환/추가 반환 수수료는 이번 전이 범위에 추가하지 않았다.

실제 입금/환불 시 계좌 이름·예금주·번호를 암호화 스냅샷으로 보존한다. 계좌 마스터 수정은 기존 확인 기록을 바꾸지 않는다. 계좌별 집계는 확인 당시 식별자로 계산하고 출력은 끝자리만 표시한다. 과거 스냅샷 없는 확인 자료는 현재 계좌로 추정해 채우지 않는다. 자금 계정에서는 기간/계정별 거래 원장을 20건씩 조회한다.

외화 자금은 원통화와 거래별 고정 환산 기록액을 함께 표시한다. 이것은 기말 재평가액·확정 환차손익이 아니다. 요청/실제 수령액과 환율 차이를 원 기록 그대로 보존한다. 세금·감가상각·외화 자금 재평가·확정 환차손익을 소계에서 제외한다. **정식 회계 마감이나 세무 장부가 아니다.**

## FIFO·물리 재고·미확정 자료

실제 QR 추적과 원가 소비층은 독립적이다. 오래된 물품이 다른 주문에 예약되어 실제로 새 배치를 출고하더라도 원가는 가장 오래된 남은 FIFO층에서 소비한다. 실제 물품 원입고가와 FIFO 잔여가를 별도 표시한다. 보유한 판매 가능·예약·반품 대기·업체 소유 A/S·불량을 자산 대상으로 하며 고객 소유로 다시 맡긴 A/S는 제외한다. 물류 단계는 재고 상태·수량·매출을 변경하지 않는다.

적용 시각 이전 물품은 최초 후속 업무 직전의 실제 보유량을 단가별 기초층으로 동결한다. 최초 수량 변경 시 이전 보유량을 복원한 후 기초를 만들고 후속 거래를 적용한다. 유지관리에서 옵션별 기초를 미리 만들 수도 있다. 소급 과거 출고 FIFO를 추정하지 않는다. 기존 미등록 원가/환율은 null과 미확정 표시를 유지하며 소계를 완전한 이익으로 표시하지 않는다. 원가가 확정된 과거 입고 단가를 수정하는 API를 제공하지 않는다.

체류는 실제 물품 입고일·창고 위치·입고 배치·물류 단계로 구분한다. 기본 주의 90일/위험 180일, 업체별 설정. 실사 손실은 기존 상태 전이 movement에서 FIFO 손실을 한 번만 생성한다.

## 저장·잠금·성능 구조

REPEATABLE READ 일관 스냅샷에서 DB 조건/집계 쿼리로 보고서를 읽고 저장한다. 조회·보고서 저장 전체 동안 업체 행을 잠그지 않는다. 같은 보고서 생성 키만 DB별 advisory mutex로 중복 생성 방지한다. 재고/지급 작업은 기존 업체 mutex와 해당 옵션/자금 행 잠금 안에서 짧게 처리한다. 정기 지출·FIFO 준비는 기존 live:maintain의 batch/seconds 상한과 단일 실행 잠금 안에서 수행한다. 운영 스케줄은 변경하지 않았다.

목록은 페이지 조회, 합계는 전체 조회 조건 집계. 현재 잔액 분석에 사용하는 과거 전표/지급·회수/주문/원가 내역도 상세에 포함하며 기간 내 활동과는 각 기록일로 구분한다. 저장은 100행씩 읽고 쓰며 상세는 100건 단위 분할 재출력한다. 각 분할에는 전체 합계, 첫 분할에는 전체 분석을 표시한다. A4 세로/가로 선택. 화면에 표시된 목록 페이지만 저장/출력하지 않는다.

업체·기간·시간대·기준 버전·생성자/시각·집계 결과·상세를 live_reports/live_report_rows에 보존한다. 기존 운영 보고서 결과는 수정하지 않는다. 재생성은 새 UUID, 동일 요청 키 재시도는 같은 UUID. 결과/각 상세의 SHA256을 확인하고 재조회한다. 상품명·주문·반품 변경은 이전 저장 보고서를 바꾸지 않는다. 관리 잠금은 저장 이후 원장 변경을 확인하고 기간 중복을 막는다. 미확정 보고서 잠금은 명시적 확인을 기록한다. 재개방은 별도 권한·사유·감사 기록이 필요하다. 정정은 역분개/후속 기록 또는 재개방 후 새 보고서로 보존한다.

권한: finance.read / expense / payment / accounts / transfer / cost / configure / close / reopen, inventory.count-confirm. 현재 기본 재무 역할은 비용 조회·입력·지급·계좌·이체, 적용 시작/설정·관리 잠금/재개방은 소유자다. 모든 원가 보고서/자산/저장 출력에는 finance.cost도 필요하다. 고객·판매 역할에는 내부 원가·자금 잔액을 노출하지 않는다.

## 스키마·공식 적용·복구

- 000008: 실사 초안/확정과 옵션 재고 revision.
- 000009: 재무 설정·분류·전표·지급/회수·자금/거래·이체·정기 규칙·관리 잠금·증빙·FIFO 기초/층/배분. 기존 입고에 원통화/환율, 실제 물품에 분배 원가/물류, 기존 계좌에 고객 안내/자금 연결, 기존 보고서에 유형 추가. 과거 업무 행을 재작성하지 않는다.
- 000010: 날짜별 자금 조회 인덱스와 이체 취소/반환 확인일.
- 000011: 실제 계좌 확인 스냅샷·집계 식별자. 기존 행은 nullable 그대로 보존하며 사후 계좌 추정으로 채우지 않는다.

작업 전 동일 시점의 DB·코드·암호화 키·파일 백업을 확보한다. 배포 대상은 이 플러그인 소스, migration, 뷰/언어/CSS/JS, manifest 5종, components.json, dist 및 문서다. 새 코어/외부 의존성 없음. 의존 manifest 스캔상 이 확장의 공개 API를 소비하는 다른 번들 확장이 없어 다른 최소 버전 변경 대상 없음.

```sh
php artisan plugin:build yutiv-live_commerce --production
php artisan plugin:update yutiv-live_commerce --source=bundled --force
php artisan route:cache
php artisan vendor:verify
```

위 명령은 격리 복사본에서 검증하며 이 작업에서 운영 실행하지 않는다. 새 기록이 있으면 migration down은 거절한다. 복구는 같은 시점 코드·DB·파일·키의 일관 복원 또는 수정 버전 전진 업데이트다. 과거 코드만 덮어쓰거나 기록을 지우는 rollback을 하지 않는다. 별도 외환 평가·세무/법정 장부·은행 실행·자산 감가상각·과거 FIFO 복원은 미지원이다.
